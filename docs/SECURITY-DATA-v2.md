# Данные, вложения и шифрование в v2.0

## Текущее поведение (v1.x)

- Данные: `data.json` в каталоге данных (`MYTASKS_DATA_DIR` или `%APPDATA%\MyTasks`), бэкапы в `backups/`.
- Шифрование (опционально): при `settings.dataEncryption=true` и наличии `MYTASKS_DATA_PASSWORD` весь JSON шифруется (AES-256-GCM, префикс `MYTASKS_ENCv1`, ключ выводится из пароля). Расшифровка выполняется при загрузке при наличии пароля.
- Без пароля зашифрованные данные прочитать нельзя; пароль не хранится в приложении.

## v2.0: структурные данные и вложения

- Структурные данные остаются в `data.json` (схема v2).
- Вложения хранятся как файлы в `<dataDir>/attachments/`, на них ссылаются метаданные в `data.json` (`attachments[]`, ссылки в задачах/заметках).
- **Важно:** на M1 шифрование `data.json` не распространяется автоматически на содержимое файлов вложений. Реализация вложений обязана явно определить режим:
  - либо вложения хранятся незашифрованными (даже при включённом шифровании JSON) с явным предупреждением в UI/документации,
  - либо вводится шифрование blob’ов/контейнера с управлением ключом (отдельное решение/итерация).

До внедрения выбранного режима нельзя заявлять о полном шифровании вложений.

## Бэкапы и перенос

- Pre-migration бэкап создаётся перед преобразованием 1.x→2.0 и не удаляется обычной ротацией.
- Резервное копирование/восстановление и перенос между ПК должны учитывать связку `data.json` + `attachments/` (конкретный формат снапшота — по реализации бэкап-сервиса; при раздельном хранении требуется переносить каталог вложений вместе с данными).
- Восстановление из бэкапа выполняется через согласованный путь (UI/сервис) с защитой от частичного состояния.

## Риски и требования

- Не затирать оригинал при ошибке миграции; сохранять возможность отката на pre-migration бэкап.
- При импорте/экспорте обрабатывать версию и целостность ссылок на вложения.
- GC сирот (файлы без ссылок / ссылки без файлов) — с осторожностью и логированием; не удалять данные молча без уверенности.
