# Миграция 1.x → 2.0

## Кратко

Версия 2.0 использует схему данных `version: 2` (см. `docs/SCHEMA-v2.md`). При первом запуске на 2.0 приложение автоматически:

1. Читает существующий `data.json` (при необходимости расшифровывает его с помощью `MYTASKS_DATA_PASSWORD`, как и в 1.x).
2. Создаёт **несгораемый** pre-migration бэкап вида `MyTasks-pre-v2-migration-*.json` в папке `backups/` (до преобразования данных).
3. Выполняет идемпотентную миграцию `1.x → 2.0` и нормализацию.
4. Сохраняет данные в формате v2.

Импорт JSON также проходит через общий конвейер `migrate → normalize`, поэтому файлы экспорта 1.x можно импортировать в 2.0.

## Что меняется в данных

- Добавляются `meta` и коллекции v2: `tags`, `smartLists`, `attachments`, `activity`.
- **Задачи:** новые поля `status`, `order`, `tags[]`, `attachments[]` при сохранении всех полей 1.x (сроки, напоминания/legacy, повторы, подзадачи, notified/snoozed и т.д.). `status` согласуется с `done`/инвариантами подзадач.
- **Заметки:** новые поля `tags[]`, `attachments[]`, `linkedTaskIds[]` при сохранении `archived` и остальных полей 1.x.
- **Настройки:** сохраняются пользовательские значения, добавляются дефолты v2 (например, параметры представлений).

## Бэкапы и откат

- Pre-migration бэкап не удаляется обычной ротацией резервных копий.
- Перед импортом и перед восстановлением создаётся защитный бэкап текущего состояния (`before-import` / `before-restore`).
- Восстановление доступно из настроек («Данные → Восстановить…», выбор файла копии) или через API приложения; восстанавливаются только файлы из папки `backups` (для программного вызова).

При ошибке миграции приложение не должно затирать исходный файл без возможности восстановления: при повреждении исходного `data.json` используется механизм восстановления из последней копии, а исходник переименовывается в `data.corrupt-*`.

## Вложения и шифрование

- Вложения хранятся отдельно от структурного `data.json` (каталог `attachments/` в папке данных). Резервные копии создают снимок связки данных и вложений; JSON-экспорт/импорт может переносить вложения в папке `<файл>.attachments` рядом с экспортируемым JSON.
- Текущее шифрование `data.json` (AES-256-GCM, `MYTASKS_DATA_PASSWORD`) не означает автоматического шифрования содержимого файлов вложений — см. `docs/SECURITY-DATA-v2.md`.

## Совместимость

- Экспорт по умолчанию — формат v2.
- Импорт принимает v1 и v2.
- Старые CSV-экспорты/колонки базовых полей сохраняют смысл; CSV может включать дополнительные поля v2 (например, `status`, `tags`).
